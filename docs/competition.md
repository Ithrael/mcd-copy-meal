目标：优化该项目直到可以做到本次比赛第一名的水平。本文记录推进顺序和证据，不把“测试通过”或“功能增加”视为目标达成。

官方规则按公开 GitHub Star 排名，截止为北京时间 2026-10-26 00:00。23:00:14 官方榜单第一名为 MCD-happy-meal，19 Star。名次仍在变化，必须持续复核，不能用该快照推断最终结果。

来源：[官方规则](https://github.com/M-China/mcd-developer-innovation-challenge/blob/main/activityGuidelines.md)、[官方榜单](https://github.com/M-China/mcd-developer-innovation-challenge/blob/main/RANKING.md)。

已检查前三类竞争产品的公开介绍：儿童营养建议、预算与热量控制、优惠决策。我们的差异应集中在“真实点法可以被别人照抄”，而不是继续增加相同的问答功能。

当前已有真实 MCP 门店、菜单、单品核价、预算约束、跨店重算和带二维码图片；13 项测试通过。缺口：漏掉套餐、分享内容缺少套餐具体选件、没有公开体验入口、仓库尚未公开或报名、没有分发材料和实际用户反馈。

## 推进顺序

1. **实用性优先**：套餐和随心配进入候选；套餐子项、数量、默认特制按真实详情构造；预算与必点约束覆盖套餐内部；计算价格只用官方返回。分享后保留具体选件，不能重新换成另一套默认餐品。
2. **传播体验**：首屏快速得到可理解的结果，分享图展示具体餐品与点法；接收者能直接查看攻略，再换店核验；清楚区分示例和实时价格。传播入口不强制分享、关注或 Star。
3. **发布交付**：公开可运行仓库、明确许可证、简单安装、可访问 HTTPS 体验、移动端验证、完整接入证据、标准报名草稿。公网部署不能携带个人账户 Token。
4. **实际增长**：准备真实使用场景的演示、介绍文案与反馈入口，按自然传播观察体验到分享和 Star 的转化；检查报名回复和官方榜单，依据真实反馈迭代。

## 第一轮实现设计

沿用 Node 和原生页面，不增加数据库、前端框架或 LLM 依赖。把套餐作为可核价的餐品，记录来自门店详情的 rounds；按限定数量构造满足口味的选件方案，与单点候选共同排序和核价。套餐内餐品也计入主食、小食、饮料与必点约束。

分享编码升级并兼容旧链接。只允许套餐名称、具体子项名称和数量；好友按自己门店的详情重新匹配每个选件。需要改选时显示缺项，禁止默默换成默认项。修改套餐时显示每轮实际可选餐品。

视觉继续使用红、黄、白与真实餐品照片。主视觉放在“可照着点”的攻略小票和餐品组合上；不增加装饰性营销区块。金额、核价时间、来源、套餐名称、内部餐品必须在同一张攻略中可识别。

## 验收证据

- 真实 MCP 返回证明套餐 roundList 与默认特制参数有效，核价成功。
- 实测同一需求加入套餐前后的可用结果；不宣称全局最低或使用未核验的优惠。
- 测试套餐内部的必点约束、饮料小食要求、数量、缺货和换店重新匹配，尤其是杯型不可被静默替换。
- 浏览器完成生成、套餐选件修改、链接分享、另一会话重算、PNG 导出与手机视口验证。
- 发布前扫描所有版本控制内容、分享内容和日志，确认无真实凭证。
- 发布与报名由真实网址、GitHub 仓库、官方报名回复证明；传播与竞争力由真实用户使用和公开 Star 表现证明。

这些是必要门槛，不能单独证明第一名水平。缺少可访问入口、报名或实际竞争数据时，目标仍保持进行中。

## 第一轮进展 · 2026-10-10

- 已实现单点、套餐、随心配共同筛选与核价，按实际 `roundList` 和默认特制发送；套餐内部、单轮饮料杯型都支持必点条件。
- 真实测试门店验证随心配 13.90 元、麦香鸡中套餐 28 元；必点麦香鸡和中薯条的点法核价 27.40 元，手动替换成无糖可口可乐中杯后仍为 27.40 元。结果只代表该店该次核验。
- v2 分享完整保留套餐选件，旧链接兼容；复制文案带具体点法，攻略图按文字动态调整行高，展示实际所选主食照片。
- 展示官方营业状态与时段，禁选未营业门店。跨店浏览器实测遇到关闭和暂停营业，已记录真实失败；成功套餐跨店实测需在计价可用时继续。
- 无服务器 Token 的生产模式演示实例已验证生成、分享、换店、超预算提示和 PNG 导出；390px 视口无横向溢出，控制台无错误。实际界面与攻略图已保存到 `docs/images/`。
- 自动测试从 13 项增加至 22 项；完成预算、杯型、套餐选件、跨店编码和脱敏约束验证。CI、MIT 许可草案、Render 配置、部署说明、报名草稿及第一轮介绍/演示脚本均已准备。
- 尚未创建公开仓库、部署公网服务、提交报名或对外发送宣传；发布与报名已向用户请求明确确认，部署平台也待用户选择。未产生真实外部用户或 Star 数据。

后续先完成公开入口、实际报名和营业时段跨店核价，再以真实用户反馈决定下一轮改动。测试通过并不代表目标完成。
